# RMUC 2026 战术情报库

覆盖 96 支队伍、613 场区域赛的交互式战术检索网页。页面提供队伍画像、伤害来源、稳定战术、秒级热力图、双方全车路线时间轴、雷达反制、空间推进、资源热控、目标节奏、判罚推断和双队对比。

双队对比使用同口径的六维战术、目标伤害、命中和历史战绩，并给出带样本置信度、估计区间及直接交手校正的模型胜率；该结果是区域赛样本估计，不是确定赛果。

综合强度与双队比较使用同一 3.7 口径：六维战术占 90%，正则化 Bradley–Terry 赛程校正赛果占 10%。六维权重为净战斗火力 18%、目标转化 32%、空间控制 14%、防守韧性 14%、资源转化 17%、适应能力 5%。这组取整权重在逐赛区滚动时间外回测中同时改善三个赛区的 Brier 分数，并提高总体、南部和北部胜负准确率；每个维度仍保留明确的战术语义，适应能力独立展示但不以低置信度条件样本过度干扰综合强度。由于所有分项均做小样本收缩，评级阈值校准为 S ≥ 75、A ≥ 65、B ≥ 55、C ≥ 45、D ≥ 35，其余为 E。

防守韧性由校正伤害交换 25%、机器人韧性 20%、前哨拒止 20%、基地拒止 25%、整体防守下限 10% 构成。前四项按逐局中位表现 70% 与下四分位 30% 聚合，整体下限直接取逐局综合防守的下四分位；随后混合有战术含义的绝对锚点和队伍相对位置，避免微小结构血量差被纯百分位放大。17mm、42mm 和飞镖属于净战斗伤害；判罚与撞击完全排除。

动态 JSON 使用统一的 `score-3.7.0` 数据版本并以 `cache: no-store` 请求，防止浏览器把新前端与旧队伍评分缓存混用。适应能力不再奖励比赛数量或单纯战术事件覆盖，只衡量红蓝条件迁移、跨对手下限、对强敌的超预期残差、前哨失守前后输出变化，以及同一对手败局后的再战表现增量。跨对手下限使用“下四分位 − 95% 中位表现”的部分残差：保留少量绝对下限信息，避免持续低迷仅因波动小而获高分，同时限制与火力、目标等维度重复。缺少成对条件样本时回归中性 50，只降低证据量。

### 评分 3.7 公式

每个原始指标先在 96 队中计算并列共享的中位秩百分位 `P`，再按有效样本数 `n` 收缩为 `50 + (P - 50) × n / (n + 6)`。维度总分是收缩后分项的加权和；缺失分项回到中性 50，而不是误记为 0。

每个维度同时公开“证据充分度”=`Σ(维度内权重 × n/(n+6))`。它不额外加分，而是把该维度各分项实际使用的收缩强度显式展示出来；雷达 TOP 名次必须与证据充分度一起解读，尤其是依赖换边、失守与复战条件样本的适应能力。

| 维度 | 分项与维度内权重 |
| --- | --- |
| 净战斗火力 | 对手校正机器人净输出 30%、机器人命中效率 25%、阵亡转化 25%、持续施压秒占比 20% |
| 目标转化 | 前哨首次施压 15%、前哨击毁与速度 25%、基地首次施压 15%、基地打开后的伤害速率 25%、飞镖/能量机关/雷达工具 20% |
| 空间控制 | 相对对手推进纵深 30%、越过中线的前压车秒 25%、中区相对在场 20%、有效场地格覆盖 25%；不再把单纯移动里程当作控制力 |
| 防守韧性 | 对手和交战量校正后的交换 25%、血量与在线率合并韧性 20%、前哨拒止 20%、基地拒止 25%、逐局整体防守下四分位 10% |
| 资源转化 | 时长归一化经济获取 25%、经济使用率 20%、机器人净伤害/金币 20%、目标净伤害/金币 15%、净输出/高热量车秒 20% |
| 适应能力 | 红蓝方迁移差 25%、跨对手下限稳定 20%、强敌超预期残差 25%、前哨失守后调整增量 20%、同一对手败局后的再战增量 10% |

综合强度为 `六维战术加权分 × 90% + 正则化 Bradley–Terry 赛程分 × 10%`。双队概率使用逐赛区滚动时间回测校准的逻辑尺度：南部 16、东部 10、北部 24；没有直接样本的跨赛区比较保守使用 20。直接交手记录仍展示为战术背景，但不进入概率：区域赛中的直接交手多为同一系列赛连续局，滚动时间回测显示简单胜负比例混合会降低 Brier 和胜负准确率。数据置信度由对局数和定位覆盖率生成，不进入任何战术分或综合强度。当前数据库中没有队伍跨两个规则版本的有效样本，因此规则版本适应不会被虚构为评分分项。

`python3 scripts/audit_scores.py` 会分别验证三个赛区的综合强度及纯六维战术分与胜率、淘汰阶段的相关性，检查 16/8/4 强区分度、六维权重一致性、防守分差、适应能力独立性和分项重复度，并按赛区检查双队胜率的 Brier 分数、对数损失与概率偏差。`python3 scripts/cross_validate_scores.py` 进一步使用 55%→70%、70%→85%、85%→100% 三段滚动时间窗，只用过去对局评分并预测之后比赛，同时检查 10% 宽度置信分箱的期望校准误差（ECE），防止训练集相关性或总体均值掩盖过拟合。CI 使用不含原始比赛内容的派生分差夹具复算权重、校准与门槛；本地有 SQLite 时可用 `--write-fixture` 重新生成。两项审计均进入 CI，任一指标跌破发布门槛即阻止部署。

雷达解析目前严格限于原始事件库中的 382 条“雷达反制 UAV”记录，可还原发起方、被反制方、对局与触发秒数。通信协议定义但原始库未保存的雷达标记进度、双倍易伤触发、加密等级和密钥解析结果不会被推断展示。运行 `python3 scripts/enrich_radar.py` 可从工作区 SQLite 重新生成 96 队的雷达明细。

目标节奏包含前哨首次受击的最早值、中位数、覆盖局率、90/180 秒内施压局率，以及逐局的首次受击、累计伤害和摧毁时间线。前哨击毁耗时严格按“血量归零时刻－首次受到该队伤害时刻”计算；未击毁或负耗时异常样本不进入最快值和中位数。队伍列表按综合强度降序显示全局排名，页面刷新后默认进入广东工业大学。

区域名次以东部、南部、北部三份《RMUC 2026 机甲大师超级对抗赛参赛手册 V2.0.0》规定的 16 进 8、8 进 4、半决赛、季军争夺战和冠军争夺战为赛制依据，再结合数据库实际胜负推导。页面区分区域冠军、亚军、季军、殿军、八强与 16 强；六维雷达标签同时显示 96 队共享名次，前 20 名显示 `TOP N`。

## 数据口径

- 历史比赛规则：南部赛区使用 V1.4.2，东部和北部赛区使用 V1.5.0。
- 当前反制建议和行为树设计参考 V2.0.1。
- 空间统计只采用通信协议 V2.0.0 定义的官方 28×15m 坐标。
- 热力图可分别查看真实红方、真实蓝方，或用 `(28-x, 15-y)` 将蓝方切换为己方归一化视角。
- 每局路线为 1 Hz 原始粒度，双方所有机器人共用同一份时间轴数据。
- 热力图先按 0.5m 格子累计筛选时段内的在场秒数，再以对数密度色阶渲染，每个格子只绘制一次。
- 热力图采用实场底图、密度层和可调设施轮廓遮罩三层合成；官方 28×15m 坐标只投影到实场图内墙 ROI，白边、外部围挡和突出结构保留作背景但不占用比赛坐标。
- 原始库没有红黄牌字段，牌色只按规则扣血比例分级推断，证据不足时保留为“牌色未知”。
- 行为树内部地图、区域 YAML 和 `sentry2_scau_two_mode_tunnel_overlay.png` 不参与位置映射。

`public/data/games` 保存 613 份双方共用时间轴，`public/data/heatmaps` 保存 96 份秒级热力数据，`public/maps` 保存规则手册实场图和官方坐标简图。原始比赛数据库和规则 PDF 不进入本仓库。
