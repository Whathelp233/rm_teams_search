# RMUC 2026 战术情报库

覆盖 96 支队伍、613 场区域赛的交互式战术检索网页。页面提供队伍画像、伤害来源、稳定战术、秒级热力图、双方全车路线时间轴、雷达反制、空间推进、资源热控、目标节奏、判罚推断和双队对比。

“兵种分析”独立覆盖英雄、工程、步兵3、步兵4、哨兵、空中和飞镖。六类机器人公开 2,990,075 条完整秒级状态，以及逐队、逐局的血量、位置、在场、阵亡、发弹、热量、功率、易伤、增益和承伤事实；飞镖公开闸门与命中事件。每个兵种同时提供 CSV.gz、JSON.gz 下载和 SHA-256 清单。网页只给出可验证事实指标的数值排名，不合成兵种总分。

双队对比使用同口径的六维战术、目标伤害、命中和赛程校正战绩，并给出带样本置信度与估计区间的模型胜率；直接交手与透明对手分作为背景展示，该结果是区域赛样本估计，不是确定赛果。

综合强度使用 4.0 口径，只由六维可解释战术事实构成，不把已经发生的胜负再次加入排名。六维权重依据《RMUC 2026 比赛规则手册 V2.0.1》第 5.8 节的胜负优先级设置先验，再以逐赛区、逐滚动时间窗回测约束：净战斗火力 8%、目标转化 56%、空间控制 12%、防守韧性 11%、资源转化 12%、适应能力 1%。基地/前哨终局状态、全队攻击伤害及剩余血量对应的目标、火力、防守合计 75%，促成维度合计 25%；火力只保留规则第三顺位的独立信息，避免与目标伤害和资源转化重复计分。双队胜率使用 4.3 校准：南部将与目标终局信息重叠较多的防守从 11% 降至 8%，空间从 12% 提至 15%；东部同赛区对局使用六维 90% 与正则化 Bradley–Terry 赛果 10%；北部将定位噪声较高的空间降至 5%，资源提高至 19%。候选模型在 276 场时序外推中的准确率为 68.5%、Brier 为 0.2137。由于所有分项均做小样本收缩，评级阈值为 S ≥ 75、A ≥ 65、B ≥ 55、C ≥ 45、D ≥ 35，其余为 E。

防守韧性由对手校正伤害交换 35%、机器人韧性 25%、前哨拒止 15%、基地拒止 15%、整体防守下限 10% 构成。基地和前哨的存活时长、终局血量、首次受击延迟与面对对手预期目标火力后的伤害抑制直接计分；机器人终局血量和有效在场补充规则中的“全队总剩余血量”。结构项合计 30%，避免与权重最高的目标转化重复计算；交换与机器人韧性合计 60%，用于识别能否持续守住阵线。各项按逐局中位表现 70% 与下四分位 30% 聚合，整体下限直接取逐局综合防守的下四分位，再混合绝对锚点和队伍相对位置。17mm、42mm 和飞镖属于净战斗伤害；判罚与撞击完全排除。

网页运行时使用 `data/v4/manifest.json` 和浏览器专用读取模型：队伍目录与总览可长期缓存，战术详情、热力图、兵种秒级数据和赛事模型按视图加载。原始审计 JSON 与下载归档继续保留。适应能力不再奖励比赛数量或单纯战术事件覆盖，只衡量红蓝弱侧下限 10%、跨对手表现下限 10%、对强敌的超预期响应 15%、前哨失守后的局内响应 35%，以及同一对手败局后的再战表现增量 30%。弱侧下限避免“两边都差但差值很小”被误判为适应强；缺少成对条件样本时回归中性 50，只降低证据量。审计同时限制适应能力与其余五维的相关性，避免把适应能力变成基础战力的重复评分。

## 界面与性能

队伍详情按总览、战术、地图、对局、兵种、纪律和对比分区；舒适/紧凑两档深色密度会保存在浏览器。桌面使用固定筛选栏，移动端使用筛选抽屉。热力图以 Canvas 合成实场地图、红蓝密度和设施遮罩，图表在浏览器空闲时加载，路线播放仅在实际播放期间申请动画帧。

`npm run check:bundle` 检查首包 JavaScript、CSS、默认目录与广东工业大学总览数据的 gzip 预算，同时禁止生产 source map。`npm run test:ui` 在 Chrome 和 Firefox 中覆盖默认队伍、按需热力、七个队伍标签、兵种页、竞猜页和移动筛选抽屉。

### 评分 4.0 公式

每个原始指标先在 96 队中计算并列共享的中位秩百分位 `P`，再按有效样本数 `n` 收缩为 `50 + (P - 50) × n / (n + 6)`。维度总分是收缩后分项的加权和；缺失分项回到中性 50，而不是误记为 0。

每个维度同时公开“证据充分度”=`Σ(维度内权重 × n/(n+6))`。它不额外加分，而是把该维度各分项实际使用的收缩强度显式展示出来；雷达 TOP 名次必须与证据充分度一起解读，尤其是依赖换边、失守与复战条件样本的适应能力。

| 维度 | 分项与维度内权重 |
| --- | --- |
| 净战斗火力 | 对手校正机器人净输出 35%、机器人命中效率 15%、阵亡转化 25%、持续施压秒占比 25% |
| 目标转化 | 前哨首次施压 10%、前哨击毁与速度 25%、基地首次施压 15%、基地打开后的伤害速率 35%、飞镖/能量机关/雷达工具 15% |
| 空间控制 | 相对对手推进纵深 25%、越过中线的前压车秒 30%、中区相对在场 35%、有效场地格覆盖 10%；覆盖格只表示到达过，不再被当成主要控制证据 |
| 防守韧性 | 对手和交战量校正后的交换 35%、血量/在线率/终局血量合并韧性 25%、前哨拒止 15%、基地拒止 15%、逐局整体防守下四分位 10% |
| 资源转化 | 时长归一化经济获取 40%、经济使用率 5%、机器人净伤害/金币 10%、目标净伤害/金币 25%、净输出/高热量车秒 20%；单纯花光金币不再被视作高效 |
| 适应能力 | 红蓝方弱侧下限 10%、跨对手表现下限 10%、强敌超预期响应 15%、前哨失守后响应 35%、同一对手败局后的再战增量 30% |

综合强度为 `六维战术加权分 × 100%`。正则化 Bradley–Terry 赛程分与透明对手分独立公开，避免历史胜负和赛程强度在排名中重复加分。透明对手分先从每个对手战绩中剔除双方直接交手，以 Beta(1,1) 先验平滑，再由一阶对手胜率 75% 与二阶对手胜率 25% 组成，并按不同对手数向 50 收缩。胜率 4.7 的滚动折只在完整官方系列赛之间切分，避免同一 BO3/BO5 的前一局泄漏到后一局；配对 Bootstrap 先求每个系列的平均损失，再让每个系列等权。三个赛区统一使用火力 8%、目标 56%、空间 12%、防守 11%、资源 12%、适应 1%；南部尺度 10，北部尺度 23，东部使用统一六维 90% + Bradley–Terry 10%、尺度 10，并仅在模型分差小于 5 时将尺度乘 0.5。该东部近分差修正改善全部三个未来时间折，系列等权改善概率 99.6%，95% 区间完全低于零。旧南部/北部专属六维权重与南部赛段、分差缩放未通过完整系列门槛，已撤销；红蓝方截距和其他结构修正也不进入概率。没有直接样本的跨赛区比较使用统一纯六维、保守尺度 22。BO3/BO5 暂用规则一致的独立二项换算；119 场完整系列赛的滚动 Brier 为 0.182572，优于直接沿用单局概率的 0.188899，且 ECE 从 9.76% 降至 4.19%。但它只改善 9 个赛区×未来折单元中的 6 个，配对改善概率 90.27%，95% 区间仍跨零，因此明确标记为“尚未达到统计发布门槛”，不再把总体均值改善误写成已充分验证。0%–100% 换算强度和额外温度修正会持续随新数据复审；当前仍保持温度 1.0。BO5 只有 6 场有效样本，仍标记为数据有限。估计区间下限覆盖完整系列时间折的平均 ECE：南部 ±14、东部 ±14、北部 ±10；跨赛区至少 ±15 并标为“探索性”。直接交手记录仍展示为背景，但不进入概率。数据置信度由对局数和定位覆盖率生成，不进入任何战术分或综合强度。当前数据库中没有队伍跨两个规则版本的有效样本，因此规则版本适应不会被虚构为评分分项。

`python3 scripts/audit_scores.py` 会分别验证三个赛区的综合强度及纯六维战术分与胜率、淘汰阶段的相关性，检查 16/8/4 强区分度、六维权重一致性、防守分差、适应能力独立性和分项重复度，并按 Matchup 4.7 的完整系列口径检查双队胜率的 Brier 分数、对数损失与概率偏差。`python3 scripts/cross_validate_scores.py` 进一步使用 55%→70%、70%→85%、85%→100% 三段滚动时间窗，只用过去完整系列评分并预测之后的完整系列，同时检查 10% 宽度置信分箱的期望校准误差（ECE），防止训练集相关性、系列内泄漏或总体均值掩盖过拟合。分层校准统一换算为“预测热门方置信度→实际兑现率”，并逐时间折展示；红蓝热门方残差差异也按系列赛等权聚类检验，避免把数据文件中的主队顺序或单轮结果误读为阵营加成。脚本还会验证 29 个子指标能够在 0.15 分发布舍入误差内重构六维分差，逐赛区、逐窗口执行子指标消融，并穷举同一维度内 1%–5% 的两两权重迁移；东部与北部额外穷举 1%–8% 的赛区六维迁移，近似对局尺度、赛段尺度、红蓝截距及每个六维整项消融均执行 20,000 次系列赛聚类 bootstrap。只有逐折 Brier 与准确率均不退步、总体至少改善 0.001、改进概率达到 97.5% 且 95% 区间上界低于零，才允许进入发布评审。CI 使用不含原始比赛内容的派生分差夹具复算权重、校准与门槛；本地有 SQLite 时可用 `--write-fixture` 重新生成。两项审计均进入 CI，任一指标跌破发布门槛即阻止部署。

雷达解析目前严格限于原始事件库中的 382 条“雷达反制 UAV”记录，可还原发起方、被反制方、对局与触发秒数。通信协议定义但原始库未保存的雷达标记进度、双倍易伤触发、加密等级和密钥解析结果不会被推断展示。运行 `python3 scripts/enrich_radar.py` 可从工作区 SQLite 重新生成 96 队的雷达明细。

## 阶段动作链与双队克制

战术页从公开的 613 局逐秒路线与队伍明细生成 96 份紧凑画像，按开局、前哨、转场、基地、防守和终盘识别 17 类动作链。每条模式同时展示发生率、触发时间、兵种、区域、红蓝方差异、结果关联、证据局与反例局。选择“我方执行队伍”后，页面会按双方能力生成最多三条确定性克制方案；样本不足时明确降级为规则型备选。

`npm run prepare:data` 会生成 `public/data/v4/tactics/*.json`。这些文件单队不超过 80 KB，仅在打开战术页或选择执行队伍时按需加载。

目标节奏包含前哨首次受击的最早值、中位数、覆盖局率、90/180 秒内施压局率，以及逐局的首次受击、累计伤害和摧毁时间线。前哨击毁耗时严格按“血量归零时刻－首次受到该队伤害时刻”计算；未击毁或负耗时异常样本不进入最快值和中位数。队伍列表按综合强度降序显示全局排名，页面刷新后默认进入广东工业大学。

区域名次以东部、南部、北部三份《RMUC 2026 机甲大师超级对抗赛参赛手册 V2.0.0》规定的 16 进 8、8 进 4、半决赛、季军争夺战和冠军争夺战为赛制依据，再结合数据库实际胜负推导。页面区分区域冠军、亚军、季军、殿军、八强与 16 强；六维雷达标签同时显示 96 队共享名次，前 20 名显示 `TOP N`。

## 数据口径

- 历史比赛规则：南部赛区使用 V1.4.2，东部和北部赛区使用 V1.5.0。
- 当前反制建议和行为树设计参考 V2.0.1。
- 空间统计只采用通信协议 V2.0.0 定义的官方 28×15m 坐标。
- 热力图可分别查看真实红方、真实蓝方，或用 `(28-x, 15-y)` 将蓝方切换为己方归一化视角。
- 每局路线为 1 Hz 原始粒度，双方所有机器人共用同一份时间轴数据。
- 热力图先按 0.5m 格子累计筛选时段内的在场秒数，再以对数密度色阶渲染，每个格子只绘制一次。
- 热力图采用实场底图、密度层和可调设施轮廓遮罩三层合成；官方 28×15m 坐标只投影到实场图内墙 ROI，白边、外部围挡和突出结构保留作背景但不占用比赛坐标。
- 原始库没有红黄牌字段，牌色只按规则扣血比例分级推断，证据不足时保留为“牌色未知”。
- 行为树内部地图、区域 YAML 和 `sentry2_scau_two_mode_tunnel_overlay.png` 不参与位置映射。
- 队伍列表的赛区名次同时给出波动范围：将每个赛区系列赛按时间切成 10 组，依次删除一组并完整重跑六维模型，展示 10 次重算与全量结果的最小—最大名次。它是赛程样本敏感性范围，不是概率置信区间，不参与强度或胜率计算。
- 胜率模型同时审计最近 3、5 个系列赛占 10%–50% 的时间衰减候选，以及按双方样本量/六维证据强度收缩概率的候选；候选必须逐时间折不劣化并通过系列赛聚类重采样才会发布。当前版本采用全历史六维事实和分赛区校准，证据量仅影响展示的不确定性，不改变点预测。
- 六维模型还审计核心四维最低项、最低两项、调和均值和能力离散度等非线性短板候选。它们不能凭最终排名直接加入综合强度，仍须满足相同的滚动时间折与系列赛聚类发布门槛。
- 聚类置信检验先在每个官方系列赛内平均各局损失，再让系列赛等权参与重采样；打满 3/4 局的系列赛不会比 2 局系列赛获得更大的统计推断权重。

`public/data/games` 保存 613 份回放 v3.1 双方共用时间轴，包含秒级位置/枪口朝向/热量/经济/基地与前哨状态、结构化事件、分级伤害归因、逐候选证据链、关键战局切片和四级装配槽位。`public/data/heatmaps` 保存 96 份秒级热力数据，`public/maps` 保存规则手册实场图和官方坐标简图。原始比赛数据库和规则 PDF 不进入本仓库。

本地有原始 SQLite 时，可运行 `python3 scripts/export_replay_data_v3.py` 重建回放数据；`python3 scripts/audit_replay_data.py` 会核对 613 场覆盖、伤害事件、装配计数和文件体积预算。

`public/data/roles` 使用 `role-data-1.1.0`：每个兵种包含轻量汇总索引和按队伍拆分的完整秒级/事件级 JSON。`public/downloads/roles` 提供对应的完整 CSV.gz、JSON.gz 和 `manifest.json`。兵种稳定性汇总排除比赛前 10 秒与后 10 秒，但下载中的原始时间线不裁剪。源库受击事件没有射手身份；伤害按可审计的兵种级模型推定：42mm 根据弹种唯一性归给英雄，17mm 按命中同秒及前 1 秒的发弹份额分配，每条记录同时提供置信度、候选兵种和归因依据，不作为射手身份或命中率。运行 `python3 scripts/export_role_data.py` 可从工作区 SQLite 确定性重建全部文件。

“赛事模拟”读取 `public/data/repechage.json`，覆盖 16 队复活赛与 32 席全国赛。页面支持按官方档位随机抽入 A/B 组，也允许同档队伍手动换组；每轮可逐场选择胜者或用综合强度胜率模型自动推演，积分榜和下一轮对手在线重算并保存在浏览器。

复活赛依据全国总决赛参赛手册 V2.1.0 模拟 A/B 各 8 队、3 轮 BO3 瑞士轮及 8 进 4 全国赛名额双败争夺。全国赛模拟 A/B 各 16 队、5 轮 BO3 瑞士轮，随后完整覆盖 16 进 8 双败、8 进 4 双败、半决赛 BO3、季军赛和决赛 BO5；28 支已公布队伍与 4 个复活赛资格占位均已纳入。模型先把单局胜率换算成对应 BO3/BO5 系列赛胜率，再按该概率抽样，因此默认自动推演允许爆冷；“最高概率路径”才固定选择热门。2,000 次蒙特卡洛提供瑞士轮出线、八强、四强和冠军概率。PDF 未内嵌双败对阵树，因此双败模拟按当前负场和模型种子透明配对、累计两败淘汰；所有预测均为竞猜沙盘，不代表官方分组或确定赛果。
