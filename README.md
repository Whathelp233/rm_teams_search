# RMUC 2026 战术情报库

覆盖 96 支队伍、613 场区域赛的交互式战术检索网页。页面提供队伍画像、伤害来源、稳定战术、秒级热力图、双方全车路线时间轴、雷达反制、空间推进、资源热控、目标节奏、判罚推断和双队对比。

双队对比使用同口径的六维战术、目标伤害、命中和历史战绩，并给出带样本置信度、估计区间及直接交手校正的模型胜率；该结果是区域赛样本估计，不是确定赛果。

综合强度与双队比较使用同一 3.0 口径：六维战术占 75%，正则化 Bradley–Terry 赛程校正赛果占 25%。六维权重为净战斗火力 18%、目标转化 20%、空间控制 17%、防守韧性 20%、资源转化 10%、适应能力 15%。由于所有分项均做小样本收缩，评级阈值校准为 S ≥ 75、A ≥ 65、B ≥ 55、C ≥ 45、D ≥ 35，其余为 E。

防守韧性由对手校正承伤 25%、机器人血量面积 20%、机器人在线率 15%、前哨血量面积 15%、基地血量面积与首伤延迟 25% 构成。17mm、42mm 和飞镖属于净战斗伤害；判罚与撞击完全排除。运行 `python3 scripts/recalculate_scores.py` 可从工作区 SQLite 重建全部评分、原始事实、分项样本和置信度。

动态 JSON 使用统一的 `score-3.0.0` 数据版本并以 `cache: no-store` 请求，防止浏览器把新前端与旧队伍评分缓存混用。评分 3.0 从逐局净事实重建六维：火力只含机器人净输出，目标单独衡量前哨/基地转化，空间衡量相对占区与场地覆盖，防守使用血量面积与在线率，资源衡量经济和热控转化，适应衡量阵营、对手、强敌、逆风及战术选项。所有分项使用同口径百分位和 `games/(games+6)` 小样本收缩；数据覆盖仅生成置信度，不参与得分。

### 评分 3.0 公式

每个原始指标先在 96 队中计算并列共享的中位秩百分位 `P`，再按有效样本数 `n` 收缩为 `50 + (P - 50) × n / (n + 6)`。维度总分是收缩后分项的加权和；缺失分项回到中性 50，而不是误记为 0。

| 维度 | 分项与维度内权重 |
| --- | --- |
| 净战斗火力 | 对手校正机器人净输出 35%、机器人命中效率 20%、阵亡转化 25%、持续施压秒占比 20% |
| 目标转化 | 前哨首次施压 20%、前哨击毁与速度 25%、基地首次施压 20%、基地净伤害转化 25%、飞镖/能量机关/雷达工具 10% |
| 空间控制 | 相对对手推进纵深 30%、越过中线的前压车秒 25%、中区相对在场 20%、有效场地格覆盖 15%、420 秒归一化机动 10% |
| 防守韧性 | 对手校正机器人承伤 25%、机器人血量面积 20%、在线率 15%、前哨血量面积 15%、基地血量面积与首伤延迟 25% |
| 资源转化 | 时长归一化经济获取 20%、经济使用率 15%、机器人净伤害/金币 25%、目标净伤害/金币 25%、净输出/高热量车秒 15% |
| 适应能力 | 红蓝方表现差的反向分 20%、跨对手波动的反向分 15%、强敌表现 30%、己方前哨失守后输出响应 25%、五类有效战术选项覆盖 10% |

综合强度为 `六维战术加权分 × 75% + 正则化 Bradley–Terry 赛程分 × 25%`。数据置信度由对局数和定位覆盖率生成，不进入任何战术分或综合强度。当前数据库中没有队伍跨两个规则版本的有效样本，因此规则版本适应不会被虚构为评分分项。

雷达解析目前严格限于原始事件库中的 382 条“雷达反制 UAV”记录，可还原发起方、被反制方、对局与触发秒数。通信协议定义但原始库未保存的雷达标记进度、双倍易伤触发、加密等级和密钥解析结果不会被推断展示。运行 `python3 scripts/enrich_radar.py` 可从工作区 SQLite 重新生成 96 队的雷达明细。

目标节奏包含前哨首次受击的最早值、中位数、覆盖局率、90/180 秒内施压局率，以及逐局的首次受击、累计伤害和摧毁时间线。前哨击毁耗时严格按“血量归零时刻－首次受到该队伤害时刻”计算；未击毁或负耗时异常样本不进入最快值和中位数。队伍列表按综合强度降序显示全局排名，页面刷新后默认进入广东工业大学。

## 数据口径

- 历史比赛规则：南部赛区使用 V1.4.2，东部和北部赛区使用 V1.5.0。
- 当前反制建议和行为树设计参考 V2.0.1。
- 空间统计只采用通信协议 V2.0.0 定义的官方 28×15m 坐标。
- 热力图可分别查看真实红方、真实蓝方，或用 `(28-x, 15-y)` 将蓝方切换为己方归一化视角。
- 每局路线为 1 Hz 原始粒度，双方所有机器人共用同一份时间轴数据。
- 热力图先按 0.5m 格子累计筛选时段内的在场秒数，再以对数密度色阶渲染，每个格子只绘制一次。
- 热力图采用实场底图、密度层和可调设施轮廓遮罩三层合成，避免热力颜色遮住地图结构。
- 原始库没有红黄牌字段，牌色只按规则扣血比例分级推断，证据不足时保留为“牌色未知”。
- 行为树内部地图、区域 YAML 和 `sentry2_scau_two_mode_tunnel_overlay.png` 不参与位置映射。

`public/data/games` 保存 613 份双方共用时间轴，`public/data/heatmaps` 保存 96 份秒级热力数据，`public/maps` 保存规则手册实场图和官方坐标简图。原始比赛数据库和规则 PDF 不进入本仓库。
